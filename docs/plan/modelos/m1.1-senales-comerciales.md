## Contrato de datos necesario (`senales_comerciales`, propuesta v0)

Un CSV o tabla de solo inserción por lote A01, con una fila por evento:

| Campo | Tipo | Regla |
|---|---|---|
| `senal_id` | texto | Único y estable |
| `cliente_id` | texto | Debe existir en `clientes` |
| `tipo` | enumeración | `cotizacion`, `renovacion_gestionada`, `oportunidad_crm`, `solicitud_cliente`, `respuesta_cliente` |
| `estado` | texto | Estado del evento en el momento del registro (`abierta`, `enviada`, `ganada`, `perdida`, …) |
| `fecha_evento` | fecha | Cuándo ocurrió en el negocio |
| `registrado_en` | fecha-hora | Cuándo quedó disponible en los sistemas: es la fecha que gobierna el uso al corte (`registrado_en <= corte`) |
| `valor_cop` | número o nulo | Opcional; nulo significa «sin dato», nunca 0 |
| `producto_id` | texto o nulo | Si aplica; debe existir en `productos` |
| `origen_sistema` | texto | CRM, correo, portal, etc. |
| `version_registro` | entero | Las correcciones crean una versión nueva, no sobrescriben |

Requisitos de integración:

- El manifiesto A01 debe declarar `datos_observados_hasta.senales_comerciales`.
- Al menos 12 meses de historia anteriores al primer corte de entrenamiento.
- Correspondencia verificable con `cliente_id`.
- Las señales generadas a partir de las listas del modelo (contactos del piloto, tareas) se excluyen como variables predictivas y solo se usan para medir el proceso.

Cuando existan, las variables propuestas (con indicador explícito de «sin información» y nunca un 0 implícito) serían:

- días desde la última cotización abierta;
- número de cotizaciones en los últimos 90 días;
- renovación gestionada pendiente al corte;
- solicitud del cliente en los últimos 30 días.

Para incorporarlas hará falta una versión de variables y un protocolo nuevos.
